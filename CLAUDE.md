# CLAUDE.md — cliodeck-app cheat-sheet

> 5-minute orientation for a Claude Code session. Dense on purpose. Links over prose.

## 1. Orientation

ClioDeck is an Electron + React + TypeScript **desktop app for historians** covering the full research cycle: **explore → brainstorm → write → export**. Local-first, RAG-powered, with Zotero / Tropy / Obsidian integrations. Users: humanities researchers (history, DH). Licence **GPL-3.0-or-later**; current version **`1.0.0-rc.6-beta.3`**.

Work happens on per-feature branches off `main` (check `git status`). As of 2026-11-11 `main` is the whole story: the fusion, the usage journal, the CM6 editor migration, the chat and slides unifications, the book-chapters chantier, the July bug campaign and phases 1 to 4 of the November bug-correction plan (from the 2026-10-30 audit) have all merged. The fusion cycle (branch `feat/fusion-cliobrain`, merged into `main` at `v1.0.0-rc.2`) **absorbed [ClioBrain](https://github.com/inactinique/cliobrain) into ClioDeck as the *Brainstorm* mode** so historians get one app instead of switching between a note-centric brainstormer and a writing assistant. See [`docs/archive/fusion-cliobrain-strategy.md`](docs/archive/fusion-cliobrain-strategy.md) and [`docs/archive/fusion-cliobrain-implementation-plan.md`](docs/archive/fusion-cliobrain-implementation-plan.md) — commit messages reference the step numbers defined there.

**Where to look first**: [`docs/status-and-remaining-work.md`](docs/status-and-remaining-work.md) is the live status reference (what is done, what remains, which documents are current). Dated snapshots live in [`docs/archive/`](docs/archive/README.md) — read those for *why* something is shaped the way it is, never for what is true now.

## 2. Architecture quick-tour

**Key services** (`src/main/services/`):
- `pdf-service.ts` — vector store, indexing (~839 lines, contains a **delegating facade for search**)
- `retrieval-service.ts` — multi-source RAG over **five corpora**: PDFs (secondary), Tropy archives (primary), optional Obsidian vault, the **manuscript being written** (opt-in `includeManuscript`) and the author's **reading notes** (opt-in `includeReadingNotes`). **Path A′** (ADR 0001, amendement 2026-09-14): the corpora keep distinct schemas but share a contract — every hit's `similarity` is on the cosine scale, `max(cosine, lexical-rank relevance)` (`backend/core/rag/relevance.ts`), and each corpus is a `CorpusRetriever` (`backend/core/rag/retrievers/corpus.ts`). **Never publish an RRF score as `similarity`**: it peaks at 1/61 and sinks the corpus below all others in the shared sort (it happened twice — manuscript, then vault)
- `reading-notes-index-service.ts` — the reading notes (`reading-notes/*.md`) as a **fifth corpus** (`includeReadingNotes`, separate `readingNoteHits` channel, one **shared** author-voice band with the manuscript since 2026-10-28 — `selectWithOwnTextBands`, 20 % of `topK` for both together, at least one slot each when both answer — and the same main-side policy, `resolveReadingNotesPolicy`: a document or collection selection **scopes** the notes to those references instead of excluding them); withheld from cloud providers unless `rag.readingNotesCloudConsent` ([`docs/reading-notes.md`](docs/reading-notes.md))
- `manuscript-index-service.ts` — the manuscript as a fourth corpus: incremental by content hash, indexed after save, best-effort ([`docs/manuscript-corpus.md`](docs/manuscript-corpus.md))
- `mcp-clients-service.ts` — lifecycle of external MCP servers (stdio + SSE)
- `fusion-chat-service.ts` — unified chat transport (IPC `fusion:chat:*`): retrieval injection wiring, MCP tools, journals
- `chat-engine.ts` — the shared chat core extracted from fusion-chat-service (agent loop, compaction, retrieval hook) — NOT legacy; single UI shell: `AssistantChat` (variants `full`/`panel`, fusion step 5 done)
- `usage-journal-service.ts` — AI usage journal sink (`.cliodeck/journal.db`, never logs prompts)
- `project-lifecycle.ts` + `project-services.ts` — **la seule porte pour changer de projet côté main** (L03-3). Une file, dans l'ordre d'arrivée : `project:create` (voie a : `createProject` écrit sans basculer, puis `lifecycle.open`), `project:load` et `project:close` y passent, et aucun handler n'appelle `projectManager.loadProject`. La table ouvre les services dans l'ordre (journaux d'abord, `operations` en dernier, donc fermé en premier : il annule les opérations de portée projet puis attend leur fin, 30 s) et les ferme dans l'ordre inverse. Un service lié au projet reçoit un `ProjectHandle`, vérifie `handle.isCurrent()` après chaque attente avant de s'installer, et détache ses champs avant d'attendre la fermeture de l'ancien. Rouvrir le projet ouvert ne relit que son manifeste, sauf si l'état de `config.json` a changé (`reopenWhen`). Si B échoue, A revient (`restoredPath`), sinon l'écran passe à l'accueil. Une fermeture d'office atteint le renderer par `project:closed`. Aucun client MCP ne démarre à l'ouverture (A10, phase 6). Quitter l'app y passe aussi (`ProjectLifecycle.shutdown`, L03-9) : voir « Démarrer et quitter l'app » au §6.
- `tropy-service.ts`, `history-service.ts`, `mode-service.ts`, `pdf-export.ts`, etc.

**Provider abstraction** — `backend/core/llm/providers/base.ts` defines `LLMProvider` and `EmbeddingProvider` with a **typed `ProviderState`** state machine (`unconfigured | spawning | handshaking | ready | degraded | failed | stopped`), never a boolean. The retrieval context is a per-turn `system` message, inserted after the mode prompt and the hints (`chat-engine.ts`, 2026-10); the compactor keeps every system message verbatim. `ChatMessageMeta.ragCitation` exists in the types but **nothing ever sets it** — do not build on it.

**Workspace layout** — `<projectRoot>/.cliodeck/` (flat):
- `config.json` (`schema_version: 2`), `hints.md`, `recipes/`, `recipes-runs/`
- `brain.db` — **the single SQLite file for every corpus and the research journal**, one table prefix per domain: `pdf_*` (secondary sources), `tropy_*` (primary sources), `obsidian_*` (vault), `manuscript_*` (manuscript corpus), `reading_notes_*` (reading notes corpus), `history_*` (research journal)
- `journal.db` — AI usage journal, deliberately a **separate file** so it can be copied and published on its own (ADR 0007)
- `hnsw.index` (PDFs), `primary-hnsw.index` (Tropy), `mcp-access.jsonl`, `security-events.jsonl`
- **The file consolidation is done** (2026-05-12, commits `3260a40`, `c044d42`, `07741ab`, `a1ca0cb`): the pre-fusion stores `vectors.db`, `primary-sources.db`, `history.db` and `obsidian-vectors.db` no longer exist on a current workspace — `migrateWorkspaceToFlat` folds them into `brain.db` on project load. What remains gated on the retrieval benchmark is **Path A** proper (ADR 0001): one *schema* (`SourceDocument` / `SourceChunk`) instead of one set of tables and one store class per corpus. Sharing a file is not sharing a schema. See [`docs/path-a-readiness.md`](docs/path-a-readiness.md).
- The authoritative map is `workspaceFiles` in `backend/core/workspace/layout.ts` (see §4 — do not change it without asking).
- Legacy `.cliodeck/v2/*` (pre-flatten) and pre-fusion v1 layouts are auto-migrated to flat on project load via `migrateWorkspaceToFlat`.

**Project types** — `article` | `book` | `presentation` (`project.json`).
- **`book`** = manuscrit à N fichiers : **pas de `document.md`**, les chapitres vivent dans `chapters/` et `project.json` porte le manifeste (`chapters[]`) plus les réglages d'ouvrage (`book.noteStyle`, `noteNumbering`, `bibliography`, `numberChapters`, `numberSections`). Types partagés : `backend/types/book.ts`. Architecture : [`docs/book-architecture.md`](docs/book-architecture.md).
- **Assemblage** — `src/main/services/manuscript-assembler.ts` produit le flux unique pour les exports, en **préfixant les identifiants de notes par chapitre** (sans quoi deux `[^1]` homonymes rendent la même note : mesuré avec pandoc).
- **Règle transverse** — le **chapitre ouvert vient de l'éditeur vivant** (`getLiveContent`), jamais du disque : sinon les frappes non sauvegardées sont ignorées (renumérotation, statistiques, exports).
- **`presentation`** édite `slides.md` (découpage partagé : `src/editor/slides.ts`).

## 3. Conventions

- **Commit messages** — focus on *why* not *what*. End with a `Co-Authored-By` trailer naming **the model actually used**:
  ```
  Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
  ```
  Keep this tracking the model in use rather than a fixed name. History of the line: `Claude Opus 4.6 (1M context)` until 2026-07-24; **Opus 5 from 2026-07-25**. Commits before that date carry the earlier trailer and are correct as they stand — do not rewrite them.
- **Never amend commits.** Never `git push --force`. Never `--no-verify`.
- **Prefer `Edit` over `Write`** for existing files.
- **Strict TypeScript** — no `any`. If truly unavoidable, `// @ts-expect-error <one-line reason>`.
- **CSS** — use theme tokens from `src/renderer/src/index.css`: `--bg-app`, `--bg-panel`, `--text-primary`, `--text-secondary`, `--text-tertiary`, `--border-color`, `--color-accent`, `--color-danger`. Never hardcode colors. For tinted states: `color-mix(in srgb, var(--color-X) N%, transparent)`.
  - **Fenêtres modales : une seule feuille pour les classes communes (H1, 2026-11).** `.modal-overlay`, `.modal-content`, `.modal-header`… et `.close-button` ne s'écrivent que dans `src/renderer/src/components/common/Modal.css`, importée au démarrage par `main.tsx`. Une règle propre à une fenêtre ou à un panneau chargé à la demande se pose sous la classe de sa racine (`.methodology-modal .modal-content`, ou `:where(<racine>)` pour garder sa spécificité) : sans portée, elle change l'allure des autres fenêtres selon les panneaux ouverts avant elles. `modal-styles-scope.test.ts` refuse une règle sans portée sur une classe commune.
- **Icons** — **lucide only** (`lucide-react` in components, the vanilla `lucide` package in the CodeMirror widgets of `src/editor`, same version). No emoji or typographic glyph (✓ ▶ ✕ ➤ ↑ 📁 …) as an icon, in JSX, in `content:` CSS or in a translated string — `no-emoji-icons.test.ts` fails otherwise. Prose arrows (→) are fine. Prefer the alias names already in use (`AlertTriangle`, `CheckCircle`, `Loader2`, `BarChart3`); `svg.lucide` gets `vertical-align: -0.125em` globally so an icon inline with text sits on the line.
- **Tests** — Vitest. Location: `**/__tests__/*.test.ts`, and `*.test.tsx` for components (jsdom, see §6).
- **Before pushing** — `npm run typecheck` (`tsc --noEmit`) and `npm run lint`. **`npm run build` does not typecheck the renderer** (Vite/esbuild strips types without checking them), so a renderer type error passes the build and fails CI. Lint must stay at **0 errors**; warnings (~360) are a known stock.
- **i18n** — keys in `public/locales/{fr,en,de}/common.json`. **Three locales, and fr↔en↔de parity is tested** — a key added to one must be added to all three. Note the blind spot the July audits found: the parity test compares locale files with each other, so it cannot see a component that never calls `t()`.
- **Engineering style guides** referenced throughout the code:
  - **claw-code lessons 6.1–6.5** — typed state machines, events over prose, partial-success first-class, infra-only auto-recovery, terminal as transport.
  - **goose lessons** — provider trait abstraction, recipes YAML, `.cliohints`, MCP extensibility.

## 4. DO NOT touch without asking

- **`backend/core/workspace/layout.ts`** — owns the flat path map (`workspaceFiles`/`ensureWorkspaceDirectories`) and the `WorkspaceVersion` detection used by auto-migration. Changing keys or detection rules ripples through every service that opens `.cliodeck/*`.
- **HNSW index format** — bumping requires re-indexing every user's corpus.
- **Tropy / Zotero parsers** — non-obvious edge cases.
- **Provider contract `backend/core/llm/providers/base.ts`** — changes ripple through 5 providers + their tests.

## 5. Common how-to (one-liners)

- **Add an LLM provider** → new file in `backend/core/llm/providers/`, register in `registry.ts`, add an adapter case in `cliodeck-config-adapter.ts`, surface in `LLMConfigSection.tsx`, store API key via `secureStorage` (auto-handled by `setLLMConfig`).
- **Add a settings section** → new component in `src/renderer/src/components/Config/`, import + render in `ConfigPanel.tsx`.
- **Add an IPC handler** → register in a `*-handlers.ts` under `src/main/ipc/handlers/`, bind in `src/preload/index.ts`.
- **Add an MCP server tool** → file in `backend/mcp-server/tools/`, register in `backend/mcp-server/server.ts`. Pattern: see `searchObsidian.ts`.
- **Add a recipe step kind** → extend `StepKind` in `backend/recipes/schema.ts`, add a handler in `backend/recipes/runner.ts` (or override via `stepHandlers` option in `recipe-step-handlers.ts`).

## 6. Known issues (state of `main`, 2026-11-11)

- **The suite is green, and the skips are legitimate.** `npx vitest run` → **0 failing**, 5 tests skipped locally: 2 need a case-sensitive disk (`project-manager-open.test.ts`), 3 need the topic-modeling Python venv `~/.cliodeck/python-venv` (`topic-service-http.test.ts`, and `TopicModelingService.live.test.ts`, which also needs `RUN_PYTHON_TESTS=1`). A machine with that venv skips fewer. Suites needing the better-sqlite3 native binding are still guarded by `describe.skipIf(!sqliteAvailable)` / per-test `it.skipIf` via `backend/__tests__/helpers/native-guards.ts` (which also provides `ollamaAvailable()`), but since better-sqlite3 13 the guard only trips when the binding is genuinely missing.
- **better-sqlite3 13 (N-API) depuis DEP-1 (#208, 2026-11-06) : un même binaire pour Node et Electron.** Le paquet charge un binaire précompilé (`prebuilds/<plateforme>.node`) sous les deux runtimes : les suites SQLite tournent en local comme en CI, et local et CI voient les mêmes tests. Jusqu'à la 12, elles étaient sautées en local et ne tournaient qu'en CI — trois exécutions rouges le 2026-07-26 en sont venues. **Avant de pousser un changement qui touche `backend/core/vector-store/*`, `HistoryManager`, `ObsidianVaultStore` ou un écrivain de `brain.db`, lancer `npm run test:integration`** : ses recompilations ne changent plus rien pour better-sqlite3, mais il finit par ouvrir une base sous Electron (restauration dans un `finally`, même quand les tests échouent). `node -e "new (require('better-sqlite3'))(':memory:')"` réussit désormais sous les deux runtimes et ne prouve plus rien ; le contrôle qui compte est `ELECTRON_RUN_AS_NODE=1 node_modules/.bin/electron -e "new (require('better-sqlite3'))(':memory:')"`. Ouvrir une base, pas seulement charger le module : better-sqlite3 lie son binding paresseusement. `hnswlib-node`, N-API lui aussi, est compilé par `electron-rebuild` et se charge sous les deux runtimes. **Depuis 2026-09-30**, `test:integration` et `project:health` sont des lanceurs Node (`scripts/test-integration.mjs`, `scripts/electron-node.mjs`) : les écritures `VAR=1 …` et `… ; …` étaient celles d'un shell Unix, inconnues de `cmd` et de PowerShell.
- **Les tests e2e Playwright tournent en local, jamais en CI** (`npm run test:e2e`, `e2e/*.spec.ts`, app réelle lancée par `_helpers/launch.ts`). Sans affichage, la CI les saute : deux des trois smoke tests étaient rouges depuis des mois sans que rien ne le dise (libellés anglais alors que l'app démarre en français, mode « Analyze » renommé « Explore », sections des réglages devenues des entrées de navigation derrière le mode Expert). Le lanceur **fixe la langue** (`E2E_LANGUAGE`, français) dans le `cliodeck-config.json` du userData temporaire : un userData neuf démarre déjà en français (`DEFAULT_CONFIG.language`), mais un test écrit sur un libellé ne doit pas dépendre de ce défaut. Lancer la suite après tout changement d'interface.
- **React component tests DO exist** — 107 `.test.tsx` files run under jsdom with `@testing-library/react` and a full `vitest.setup.ts`. The line that used to claim the setup was "pending" was wrong; the 2026-07-25 audit caught it. Coverage is still thin, but the harness is there — add to it rather than re-scaffolding.
- **Ollama provider exposes `capabilities.tools` per-model** via a whitelist (`ministral-3:8b/14b`, `qwen3:8b/14b/32b`, `mistral-nemo`); other models (notably the Llama 3.x and 4.x families) get `tools: false`. So a provider's `tools` capability is a function of its **configuration**, not its identity — do not cache it across a model change. See `OLLAMA_TOOL_CAPABLE_PATTERNS` in `backend/core/llm/providers/ollama.ts`, `docs/archive/research-ollama-tools-1.8.md` for the source-cited rationale, and the 2026-07-25 amendment to ADR 0004. The 4 cloud providers (OpenAI-compatible, Anthropic, Mistral, Gemini) advertise tool-use unconditionally.
- **Electron 45 depuis le 2026-11-06 (ELEC-1, #210) — quatre règles pour le code** (l'installation et l'empaquetage sont dans [`docs/empaquetage.md`](docs/empaquetage.md)). La série 43 n'était plus suivie après le 2027-01-05 ; la 45 l'est jusqu'au 2027-04-27. Les deux premières règles datent de la 43 (#146).
  - **Un dialogue sans `defaultPath` s'ouvre dans « Téléchargements »** et le système ne retient plus le dernier dossier. Les deux seuls appels à `dialog.show*Dialog` (`filesystem-handlers.ts`) passent par `resolveDialogDefaultPath` et retiennent le dossier du dernier choix dans la configuration (`lastDialogDirectory`). Tout nouvel appel doit faire de même.
  - **`printToPDF` compte `pageSize` en pouces.** L'export PDF des présentations lui passait des microns et n'activait pas le mode impression de reveal.js (`?print-pdf`, lu dans l'URL) : une seule diapositive sur des pages de 6 km, en silence, puis un échec franc sous Electron 43 (#148). C'est le seul chemin qui imprime par Chromium ; `e2e/journey-presentation-pdf.spec.ts` le couvre — à relancer à chaque montée d'Electron.
  - **La première page d'une fenêtre est le document vide, avant `loadFile`.** Un pilote Playwright attend l'URL de l'app (`waitForURL`, comme `e2e/_helpers/launch.ts`), jamais le seul `domcontentloaded` de `firstWindow()` : sinon il rend la main avant le montage de React, et un événement envoyé aussitôt se perd (7 tests e2e en échec avant le correctif).
  - **`safeStorage` synchrone est déprécié en 45 et retiré en 46** (le journal l'affiche à chaque lancement). Réécrire `secure-storage.ts` et `scripts/set-archive-key.cjs` en asynchrone (`isAsyncEncryptionAvailable`, `encryptStringAsync`, `decryptStringAsync`), en reprenant les données existantes, avant la montée suivante.
- **Empaquetage, signature, notarisation, montées d'Electron et d'electron-builder : lire [`docs/empaquetage.md`](docs/empaquetage.md) avant tout build de distribuable, toute montée de version ou tout essai d'une app empaquetée.** Trois règles valent même sans l'avoir lu :
  - **ne pas retirer le crochet `mac.sign`** (`scripts/mac-sign.cjs`) : sans lui, `codesign` ne retrouve pas le certificat, dont le nom est accentué ;
  - **une app empaquetée non signée se lance toujours avec `--use-mock-keychain`**, sinon elle reste bloquée sur le trousseau réel et `SIGTERM` ne l'arrête pas ;
  - **après une montée d'Electron, `npm update node-abi`** ; les modules natifs se recompilent par `electron-rebuild --force` (`npm run rebuild:native`), jamais par `electron-builder install-app-deps`.
- **Sous macOS 13, pas d'Ollama — mais les modèles embarqués restent.** L'app exige macOS 13 depuis Electron 45 (`build.mac.minimumSystemVersion`, décision T7) : sous macOS 12, le Finder refuse de la lancer. `v1.0.0-rc.6-beta.3` est la dernière version publiée qui y tourne. Ollama exige macOS 14 et ne s'installe pas en dessous. Le moteur embarqué (`node-llama-cpp` précompilé) déclare `minos 14.0` dans les deux architectures (`vtool -show-build`), ce qui ne l'empêche pas de tourner : sur un Mac Intel sous macOS 12, le modèle de génération embarqué répond. **Le moteur embarqué calcule aussi les embeddings** (`EmbeddedEmbeddingProvider`, modèle Nomic Embed v2, 344 Mo). **Vérifié le 2026-10-06 sur un vrai Mac Intel sous macOS 12**, avec le DMG notarisé : un projet réel s'indexe et le chat répond, embeddings et génération venant tous deux des modèles embarqués, sans Ollama (#128) — lentement sur une machine de cet âge, mais de bout en bout. C'était sous Electron 43 : à revérifier sous macOS 13 avec la 45. Les deux sections — « Modèle embarqué (Qwen) » et « Embeddings (recherche sémantique) » — ne sont visibles qu'en **mode Expert** des paramètres : on peut utiliser l'app longtemps sans savoir qu'elles existent. `useLocalAiSupportWarning` dit tout cela au premier lancement sous macOS < 14, puis s'en souvient (`localAiNoticeDismissed`) — une limite du système sans remède dans l'app ne se redit pas —, alors que `useSandboxWarning` revient à chaque lancement. Les deux reposent sur `useStickyWarning` : tout nouvel avertissement de démarrage doit passer par lui.
- **Ouvrir un document (2026-11, Q9).** Le repli d'ouverture (`openProjectContents`) ne crée le fichier que sur `code: 'absent'`, en écriture exclusive, hors livre. `editor:load-file` lit en UTF-8 strict : un fichier qui n'est pas en UTF-8 est refusé, intact ; tout écrivain qui relit un fichier de l'auteur passe par `updateFile`, jamais par `readFile(…, 'utf-8')` suivi d'une écriture.
- **Le texte de l'historien ne se perd plus : quatre règles (phase 1 du plan de correction, 2026-11).**
  - **Écrire un fichier de l'historien passe par l'écriture atomique** (`atomicWriteFile`, `backend/core/fs/user-files.ts`) : jamais d'écriture en place qu'une coupure laisserait à moitié.
  - **Remplacer le document ouvert passe par une seule fonction**, `editorStore.replaceBuffer` : aucun autre chemin ne change le fichier ouvert, sauf « Enregistrer sous ».
  - **Aucun changement de document pendant une renumérotation** : le verrou (`manuscriptStore.renumbering`, `editorStore.switchLock`) bloque l'ouverture d'un autre chapitre et les exports tant que la boucle écrit.
  - **`--use-mock-keychain` vaut aussi pour l'Electron non empaqueté du dépôt** (tests e2e, pilotage par Playwright) : sans lui, Electron peut rester bloqué sur le trousseau réel. `e2e/_helpers/launch.ts` le passe déjà.
- **Synchro Tropy — chemin réparé le 2026-08-30, à ne pas re-casser.** Cinq défauts y faisaient perdre en silence l'intégralité d'un OCR de corpus (~24 h de calcul, mesuré sur un projet réel de 221 documents). Deux règles à garder en tête :
  - **La fraîcheur d'un item se lit sur `subjects.modified` (par item), jamais sur la mtime du `.tpy`** (globale au projet). C'était l'erreur d'origine : plus aucune source n'était jamais vue comme « modifiée », donc jamais sauvegardée, alors que l'OCR tournait quand même — avant la décision d'écriture.
  - **Jamais `INSERT OR REPLACE` sur une table qui a des enfants** — piège rencontré deux fois (sources Tropy ; puis `pdf_zotero_collections` en rc.6, #130, où REPLACE effaçait les liens document ↔ collection et, via `parent_key … ON DELETE SET NULL`, détachait des sous-collections de leur parent). REPLACE supprime la ligne en conflit ; `PrimarySourcesVectorStore` ouvre avec `foreign_keys = ON` et quatre tables filles sont en `ON DELETE CASCADE`. Réenregistrer une source emportait ses chunks (46 → 0, mesuré) et ses mentions d'entités — photos et tags, réinsérés juste après, masquaient le trou. Utiliser `ON CONFLICT(id) DO UPDATE`.
  
  Quatre règles de plus depuis la phase 3 du plan de correction (2026-11) :
  - **Identité du projet Tropy lié (L06-3).** Elle se lit dans `project.project_id` du `.tpy`, rangé dans `tropy_projects.project_uuid`. Un projet ClioDeck, un projet Tropy (Q25) ; la garde est dans `TropySync.sync`, avant toute écriture. Ne jamais rapprocher une source par `tropy_id` hors du projet lié. Ouvrir en lecture seule un `.tpy` en WAL crée ses `-wal`/`-shm` et les laisse : toute lecture du `.tpy` passe par `openTropyDatabase` (`tropy-database.ts`), qu'emploient `TropyReader` et la lecture d'identité (G2).
  - **OCR et tesseract.js 7 (L06-10).** Un modèle de langue qui ne se charge pas laisse la promesse de `createWorker` sans réponse : toujours un `errorHandler` et un délai (`TropyOCRPipeline.initialize`). Les modèles vivent dans `<userData>/tesseract-cache` ; sans `cachePath`, ils iraient dans le dossier courant, `/` pour l'app lancée du Finder.
  - **OCR partiel (L06-10).** `tropy_sources.ocr_pending = 'poppler'` marque une transcription partielle : la passe OCR suivante la reprend ; un texte partiel ne remplace jamais une transcription acquise. Deux autres valeurs depuis G3 : `'pages'` (pages changées, ci-dessous) et `'pages-poppler'` (pages changées d'une transcription partielle).
  - **Langue de l'OCR (L06-11).** Ne jamais appeler `worker.reinitialize` de tesseract.js 7 : `initialize(language)` recrée le moteur à chaque changement de langue. La confiance est pondérée par la longueur du texte, et `pageCount` compte les pages reconnues.
  
  Trois de plus depuis la phase 4 (2026-11) :
  - **Pages changées (G3).** `ocr_pending = 'pages'` marque une source OCRisée dont l'ensemble des photos a changé depuis la synchro précédente. Chaque ouverture contrôle donc l'index contre la base (`checkHnswIndex`) et le refait par tranches s'il est en retard. Ne jamais reconstruire d'un bloc les index des sources primaires depuis un chemin de l'app, interface comprise (`rebuildAllIndexes` : 102 s de gel sur 40 650 extraits) ; passer par `rebuildIndexesInSlices`. hnswlib relit un index écrit vide avec une capacité nulle : `resizeIndex` à la lecture. Toute comparaison entre l'index et la base compte à une seule dimension (`length(embedding) = dimension * 4`). La recherche ne reconstruit jamais l'index d'un bloc : elle lance `rebuildIndexesInSlices`, et l'index courant sert en attendant.

Toute écriture passe par `toStoredPath`, toute lecture par `fromStoredPath` ou `mergeCitationsWithMetadata(…, projectPath)`. Ne jamais comparer ni ouvrir un `localPath` brut lu sur le disque.

Seul un projet qui ne nomme aucun `.bib` part d'une bibliographie vide ; `!expected && !existsSync(bibtexPath)` (`zotero-service.ts`) fait naître `bibliography.bib` à cette première synchro.
- **PDF corpus: one file, one document (2026-09-14).** `PDFIndexer.indexPDF` used to add a new document (random id, full chunk set) on every call, and only a renderer-side in-memory set guarded against it — measured on a real project: 221 documents for 55 PDFs, 5 920 chunks of which 1 264 distinct, copies crowding the retrieval `topK`. Indexing a file already present now **replaces** it (`mergeDocumentsInto`, after the new chunks are written, re-pointing incoming citations and Zotero collections); `pdfService.init` removes legacy duplicates after a `brain.db.avant-dedoublonnage-<date>` backup. **"One file" means one file on disk, not one path string (#123, rc.6):** documents are matched by real path (`backend/core/vector-store/file-identity.ts`, `realpathSync.native`), because macOS ignores case — a PDF renamed by case only (Zotero rename) and reindexed used to become a second document, invisible to both the dedup and the health check. Never compare `file_path` with `=` / `GROUP BY` to decide identity. HNSW/BM25 cannot remove a vector: any document deletion marks `EnhancedVectorStore` stale and `pdfService.scheduleIndexRebuild` rebuilds once in-flight indexing is done; search drops hits whose document is gone.
  - **Indexation tout ou rien (L02-7, 2026-11).** Tous les embeddings d'abord, puis document, citations, extraits et remplacement des copies dans une transaction (`VectorStore.transaction`) ; HNSW et BM25 ensuite (`addToSearchIndexes`), marqués périmés en cas d'échec. Le renderer compte un document indexé si `chunkCount > 0`, `lowText` ou `noChunks`.
  - **`mergeDocumentsInto` rattache toutes les tables filles de `pdf_documents` avant le `DELETE` (L02-10, 2026-11).** Huit clés étrangères pointent sur `pdf_documents(id)` : extraits (CASCADE), citations sortantes (CASCADE) et entrantes (SET NULL), similarités (CASCADE, des deux côtés), affectations de thèmes et aberrants (CASCADE), collections (CASCADE). Les citations entrantes, les collections, les affectations et les aberrants se rattachent au document gardé, avec une seule place par analyse ; la taille des thèmes touchés se recompte. Les extraits et les similarités de la copie partent, et la réindexation les recalcule. Toute nouvelle table fille de `pdf_documents` s'ajoute à `mergeDocumentsInto` dans la même PR. `saveDocument` est en `ON CONFLICT(id) DO UPDATE`, jamais `INSERT OR REPLACE`. `saveTopicAnalysis` écrit tout ou rien et écarte les documents disparus pendant le calcul.
- **Le texte extrait d'une page de PDF est une seule ligne, sans aucun saut de ligne (mesuré : 0 sur 807 pages).** Tout code qui cherche des lignes ou des paragraphes dans ce texte tourne à vide : dans `AdaptiveChunker`, le découpage par défaut, la détection des titres de section ne reconnaît donc rien sur un PDF (la bibliographie n'est jamais écartée, le préfixe « Section : » jamais posé), et chaque page formait un « paragraphe » jamais recoupé (#157). Deux règles depuis 2026-10-05 : **la taille d'un extrait se garantit à la phrase**, pas au paragraphe ; **la page et la position d'un extrait voyagent avec son texte** (`SourceLine`), elles ne se recalculent jamais à partir de longueurs cumulées — le recouvrement y était compté deux fois et la page citée par l'assistant prenait une page d'avance tous les huit à dix extraits (#160). Tout changement du découpage ne vaut que pour les PDF réindexés.
- **PDF extraction: pdfjs-dist 5, one loader, Electron's Node (rc.6, #77).** Load pdfjs **only** through `backend/core/pdf/pdfjs-loader.ts` and never call `page.render()` — `pdfjs-no-render.test.ts` fails otherwise (rendering is the CVE-2024-4367 path). Under Node, pdfjs 5 dies on « DOMMatrix is not defined » unless `DOMMatrix`/`ImageData`/`Path2D` exist; the loader installs method-less placeholders instead of relying on `@napi-rs/canvas`, which is prebuilt per architecture (the Intel DMG built on Apple Silicon only carries the arm64 binary). pdfjs still `require`s it unconditionally, so it is excluded from packaged apps (`build.files`) and its expected multi-line warning is silenced during import — otherwise every PDF would log a fake `[pdf-worker:err]`. The extraction worker runs on `process.execPath` + `ELECTRON_RUN_AS_NODE=1`, **not** a system `node` (most users have none; pdfjs 5 needs Node ≥ 22.13). Before touching that path, run `scripts/pdf-extraction-snapshot.mjs` on real PDFs and compare.
- **The manuscript corpus is fully wired since rc.4.** Three defects were fixed: its hits carried an RRF score (max ≈ 0.016) against the other corpora's cosine (threshold 0.12) and were crowded out of `slice(0, topK)` — `retrieval-service.ts` now publishes the real cosine and gives the manuscript a **band** of slots (`retrieval-quota.ts` — floor *and* cap since 2026-10: the rc.4 reserve was a floor without a ceiling and the manuscript, written in the question's language, took the rest "au mérite" until it was alone in the prompt; see [`docs/poids-du-manuscrit.md`](docs/poids-du-manuscrit.md)); `manuscript:index` / `manuscript:stats` were registered in main but **absent from the preload**, hence unreachable; and nothing in the UI called them. `ManuscriptCorpusSection` (Settings → expert) now shows the index state — pieces, extracts, last-indexed date — offers a re-index button and exposes `rag.indexManuscript`. Known edge: the panel reads its state on mount, so figures go stale if you leave Settings open while writing. **Since 2026-10 the manuscript's place in a turn is a policy** (`src/main/services/manuscript-policy.ts`, resolved main-side every turn): explicit recall question (`backend/core/rag/manuscript-intent.ts`, deterministic, fr/en/de) > manuscript-only scope > scope the user restricted > the « Mon manuscrit » toggle (tri-state, off by default in the Brainstorm workspace) > the chat mode's `ragOverrides.manuscript` stance (`off` | `background` | `recall`). The reading notes follow the same policy (`resolveReadingNotesPolicy`, toggle « Notes de lecture », `ragOverrides.readingNotes` falling back to the manuscript's stance), with one difference: a document or collection selection scopes them by citation key instead of excluding them. Never reintroduce an unconditional `includeManuscript` or `includeReadingNotes`. **The manuscript embeds only what the author wrote**: blockquotes and reference footnotes (under 25 words) leave the indexed text (`chunkManuscriptChapter(…, { dropQuotations: true })`, manuscript indexer only — reading notes keep their quotations). `CHUNKER_VERSION` is part of each chapter's content hash: bump it whenever the chunker's output changes, or nothing gets re-embedded.
- **Corpus en panne et corpus vide (E2, 2026-11).** Un corpus en panne lève, un corpus sans extrait rend `[]` : `fanOutCorpora` en fait `ok: false` ou `ok: true, hitCount: 0`. Ne jamais avaler une exception de recherche dans un `catch` qui rend `[]`.
- **Liens web (E1, 2026-11).** Un lien de la page s'ouvre par le preload (`openActivatedLink` : clic réel `isTrusted`, Cmd+clic, clic du milieu, Entrée → `shell:open-external`). - **Changer de projet (phase 4, 2026-11).**
  - **Services de projet hors de la séquence (L03-3).** Ne jamais ouvrir ni fermer un service de projet hors de la séquence de `project-lifecycle.ts`, et ne jamais y comparer le dossier d'un autre projet par un appel synchrone au disque : un volume mort gèlerait le main hors de toute borne.

Un chargeur capture le handle (`projectLifecycle.capture()`) et n'écrit pas une réponse arrivée après la bascule ; il ne remplace pas `stillIn`. Jamais deux voisins avec la même clé : React laisse l'ancien monté à chaque bascule, d'où les cinq « Paramètres Zotero » trouvés par l'e2e. Préfixer (`actions:${path}`). Jamais de clé sur `ProjectPanel` (l'accompagnement lancé après `createProject` serait perdu) ni sur `MainLayout` (la vue CM6 serait recréée sur l'ancien fichier). La clé est le chemin : le même projet rouvert ne remonte rien.

  - **Message d'une écriture manquée (L03-5).** Un message qui dit qu'une écriture n'a pas eu lieu se décide sur la réponse du main, pas sur l'état du renderer : une écriture déjà partie peut aboutir après une fermeture d'office (`fs:write-file` valide, puis écrit). Le poser tout de suite et le retirer quand la file a sa réponse (`ideasSettled`) ; ne jamais en poser un tard.

Sinon il s'arrête sans rien écrire : une passe abandonnée n'écrit plus rien, ne purge rien (sa liste des entrées vues est partielle), et ne pose pas le compte rendu affiché par le projet suivant. Le refus remonte comme `project-changed` (`ProjectChangedError`), que le renderer reconnaît sans alerte (`refusedAsProjectChanged`, `projectLifecycle.capture()`). Côté renderer, une opération longue liée à un projet vérifie `refusedAsProjectChanged(result) || !(await stillIn(path))` : le handle de `projectLifecycle` finit à toute demande au main, même quand A reste à l'écran.

Une fermeture n'attend que les recherches du magasin qu'elle rend. Une recherche capture son magasin à l'entrée et vérifie son numéro après chaque attente : restée au-delà du délai, elle lève `project-changed`, jamais une erreur SQLite ni une réponse du projet suivant. Tout nouveau lecteur d'un magasin de projet à travers une attente suit ce patron. Une reconstruction programmée ne vaut que pour le magasin où elle a été demandée (`scheduleIndexRebuild(store)`) : jamais `this.vectorStore` lu au départ d'un minuteur.
- **Démarrer et quitter l'app (phase 4, 2026-11).**
  - **Quitter l'app (L03-9).** La sortie est bornée : `before-quit` = `mayLeaveRenderer`, puis les fenêtres masquées, puis `shutdownApp` (8 s : projet par `ProjectLifecycle.shutdown`, service des thèmes, modèles embarqués), puis `app.exit()` quoi qu'il arrive. À la sortie, chaque attente de fermeture n'a que sa part du temps restant : les journaux (recherche, usage), fermés les derniers, se ferment dans l'échéance, même pendant une bascule déjà en cours ; le gestionnaire de projet reste ouvert jusqu'à `app.exit`, pour une écriture tardive du renderer. Un modèle embarqué est suivi dès le début de son chargement (`embedded-engine-pool.ts`), et plus aucun ne se charge une fois la sortie commencée. Jamais `llama.dispose()` : il libère le backend de tout le processus.
  - **Démarrage et menu (L03-10).** Un fichier de réglages illisible (`cliodeck-config.json`, `cliodeck-secrets.json`) est mis de côté par `quarantineFile` (`openStoreResilient`) et l'app s'ouvre avec les défauts. Toute autre erreur donne une boîte d'erreur, qui nomme aussi les copies déjà faites, puis `app.exit(1)` : l'app ne reste jamais sans fenêtre. Une commande de menu résout sa fenêtre au clic, attend que le renderer l'écoute (`menu:listening`) et part dans l'ordre des clics : tout canal `menu:*` envoyé par le menu doit être écouté dans `useMenuShortcuts`. Une fois la sortie engagée, le menu ne fait plus rien (`QuitHandler.isLeaving`). Un dialogue posé dans `whenReady` se simule en e2e par un module `-r` (`launchApp({ startupDialogs: true })`).

## 7. Glossary

- **Manuscript corpus** — the historian's own text, indexed as a fourth corpus so the assistant can answer « what have I already written about X? ». Extracts are labelled `manuscrit`, never « bibliographie » — the author must see when they are citing themselves.
- **`manuscript` vs `book` — the boundary that trips people up.** `book` is a **project type** (how the text is stored: N files in `chapters/`, no `document.md`). *Manuscript* is a **semantic notion** (whose text it is: the author's own, as opposed to their sources) and exists in all three project types — `document.md` for an article, `slides.md` for a presentation, the chapters for a book. The trap is that the code uses the word at two levels: `manuscript-index-service` / `ManuscriptStore` (backend) really do mean **the fourth RAG corpus, all project types**, whereas `manuscriptStore` (renderer), `manuscript-assembler` and `ManuscriptSearch` are **book-only in practice** — `manuscriptStore.refreshAll` returns immediately when `chapters.length === 0`. Read `manuscriptStore` as *book outline store*; it is misnamed, not general.
- **`.cliohints`** — workspace-level system-prompt context, persists across chats (`.cliodeck/hints.md`).
- **Recipe** — YAML-defined workflow chaining brainstorm / search / graph / write / export steps.
- **Vault** — an Obsidian markdown notes folder, indexed in the `obsidian_*` tables of `.cliodeck/brain.db`.
- **Note de lecture** — one Markdown file per reference in `reading-notes/` (front matter: `citekey`, `zotero_key`, project `tags`). Project-owned and editable; Zotero tags and notes are Zotero-owned and read-only (automatic Zotero tags hidden by default). Never written to the `.bib`. See [`docs/reading-notes.md`](docs/reading-notes.md).
- **Primary source** — Tropy archive (archival photos, OCR'd documents).
- **Secondary source** — PDF in the bibliography (published article, book chapter).
